# 架构评审模板

## 一、评审目的

架构评审用于在项目关键节点对技术方案进行集体评估，确保方案在可行性、可扩展性、性能、安全与成本等方面达到要求，降低后期返工风险。

| 评审阶段 | 立项 / 详细设计 / 上线前 |
| 提交人 | （填写） |
| 评审日期 | （填写） |
| 参与评审人 | （填写） |

## 三、背景与目标

- 业务背景：说明需求来源与要解决的核心问题。
- 目标与非目标：明确本方案要达成的目标，以及本次不覆盖的范围。
- 关键指标：如性能指标、容量规划、可用性目标（SLA）。

## 四、方案设计

### 4.1 总体架构

- 系统上下文与边界
- 核心模块划分与职责
- 关键数据流与调用链路

### 4.2 技术选型

- 选型对比：候选方案的优劣势与选择理由
- 依赖组件：数据库、缓存、消息队列、检索引擎等
- 与现有技术栈的一致性

### 4.3 数据设计

- 核心数据模型与关系
- 数据量预估与增长趋势
- 索引与分区策略

## 五、非功能性设计

- 性能：QPS、响应时间、瓶颈点与优化手段
- 可用性：容灾、降级、限流与熔断
- 安全：鉴权、数据加密、敏感信息处理
- 可观测性：日志、监控、告警与链路追踪

## 六、风险与权衡

- 主要技术风险与应对措施
- 关键权衡点（如一致性 vs 性能）
- 遗留问题与后续演进计划

## 七、评审结论

- 结论：通过 / 有条件通过 / 不通过
- 待办事项与责任人
- 复审时间（如需要）
