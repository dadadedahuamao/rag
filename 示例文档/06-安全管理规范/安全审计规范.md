# 安全审计规范

## 一、目的与范围

为规范公司信息系统的安全审计工作，实现关键操作可追溯、异常行为可发现、合规要求可验证，特制定本规范。适用于公司各类业务系统、基础设施与安全设备。

## 二、审计对象

- 账号与认证：登录、登出、认证失败、密码变更、MFA 事件。
- 权限变更：授权、回收、角色调整、提权操作。
- 数据操作：敏感数据的查询、导出、修改、删除。
- 系统与配置：关键配置变更、服务启停、策略调整。
- 安全事件：告警、拦截、隔离等安全设备事件。

## 三、日志要求

### 3.1 记录内容

每条审计日志应至少包含：

- 时间戳（统一时区、可信时间源）
- 操作主体（账号/身份标识）
- 操作类型与对象
- 来源信息（IP、终端、会话标识）
- 结果（成功/失败）

### 3.2 完整性与留存

- 日志应防篡改，采用集中收集与只读存储。
- 留存期限不少于法规与业务要求（通常不少于 6 个月，重要系统更长）。
- 禁止随意删除或修改审计日志。

## 四、审计流程

1. 采集：统一日志平台集中收集各系统审计日志。
2. 分析：结合规则与基线，识别异常与违规行为。
3. 告警：命中风险规则时实时告警并通知责任人。
4. 处置：对确认的问题进行处置并记录。
5. 报告：定期形成审计报告，汇报审计发现与整改情况。

## 五、审计场景示例

| 场景 | 关注点 |
| --- | --- |
| 异常登录 | 异地/非常规时间登录、频繁失败后成功 |
| 数据导出 | 大批量导出敏感数据 |
| 权限异常 | 短时间内多次提权或越权访问 |
| 账号异常 | 长期未用账号突然活跃 |

## 六、职责分工

- 信息安全部门：制定规则、执行审计、输出报告。
- 系统 Owner：配合日志接入与问题整改。
- 内审/合规：对审计工作本身进行监督检查。

## 七、附则

本规范由信息安全部门负责解释与更新，全体相关人员须配合执行。
